# enrichlite

Client-side gene-set over-representation analysis (ORA). Paste a gene list, pick
a species and collection, and get a hypergeometric enrichment table plus
publication-ready charts. Everything runs in the browser: no server, no live API
calls, no data leaves your machine. The gene-set data is prepared at build time
in Python and shipped as static JSON, so the published site only ever loads JSON
and runs JavaScript (computation in a Web Worker).

Live: https://robinsonvidva.com/enrichlite/ (also
https://robinson-vidva.github.io/enrichlite/).

## Features

- Collections: GO (BP / MF / CC), Reactome, MSigDB Hallmark, for human and mouse.
- Human (HGNC, upper-case) and mouse (MGI, title-case) are separate universes
  with separate symbol tables; matching is case-insensitive within a species
  only (no on-the-fly ortholog conversion). An alias map (NCBI synonyms) is used.
- Statistics: one-tailed hypergeometric test (equivalent to the one-sided
  Fisher's exact test), numerically stable via Lanczos log-gamma. Reports fold
  enrichment, overlap counts, and the overlapping genes. Multiple-testing
  correction with Benjamini-Hochberg FDR (default) and Bonferroni.
- Background options: annotated-in-collection (default), all protein-coding, or a
  custom pasted background; the N used is always shown.
- Optional IEA (electronic) GO annotations via an explicit toggle; default is
  curated-evidence-only (IEA excluded).
- Results table: sortable columns, pagination, and display-time filters (size
  range, min fold, min overlap, term-name search) that also drive the charts and
  exports.
- Charts (hand-rolled SVG, no dependency): dot plot and bar plot, top-N selector,
  colorblind-safe FDR colormaps, SVG and PNG export.
- Auto-generated, copy-pasteable figure legend and methods paragraph built from
  the actual run (records the test, background + N, correction, data versions,
  and whether IEA was included).
- Exports: CSV / JSON / copy-as-TSV, all with a provenance line; shareable
  permalink that encodes and restores the full analysis state in the URL hash.

## Run locally

```
python3 -m http.server 8000
```

Open http://localhost:8000/ . The committed `data/` JSON is what the live site
serves, so the page is fully functional offline.

## Rebuild the data

The data under `data/` is regenerated by the Python build script from
authoritative sources (nothing is hand-curated).

```
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python3 scripts/build_genesets.py --go --with-iea --cache-raw
```

Build flags:

- `--go` builds the GO collections (downloads go-basic.obo and the species GAFs;
  parses with goatools; true-path propagation over is_a + part_of). Without it,
  only Hallmark + Reactome are built.
- `--with-iea` additionally emits the IEA-included GO variants
  (`go_*_iea.json`); the default no-IEA variants are always built.
- `--cache-raw` saves every downloaded source into `data/raw/` and reuses it on
  later runs (and prints downloaded-vs-cached per source). Clear with
  `rm -rf data/raw/`.
- `--min` / `--max` set the GO term-size bounds (default 5 / 500).

GO evidence policy in the build: `ND` is always dropped, `NOT`-qualified
annotations are dropped, and `IEA` is excluded from the default variant (kept in
the `--with-iea` variant). The build is deterministic: rebuilding from the same
cached sources produces byte-identical JSON (only the manifest version token
changes). `codingN` (the protein-coding count) is independent of GO/IEA genes.

MSigDB note: the build auto-detects the latest MSigDB release on the public
mirror. If the mirror requires auth, download the Hallmark GMTs manually and drop
them in `data/raw/` (e.g. `h.all.v2026.1.Hs.symbols.gmt`,
`mh.all.v2026.1.Mm.symbols.gmt`), then re-run; the build stops with instructions
rather than guessing.

## Tests

```
node tests/test_stats.js           # hypergeometric / BH / Bonferroni numerics
node tests/test_data.js            # built-data + per-collection sanity guards
python3 tests/test_propagation.py  # GO true-path propagation, namespace isolation, GAF filtering
```

## Project layout

```
index.html, methods.html   static pages (index loads app.js via a no-cache bootstrap)
css/styles.css             styles
js/stats.js                pure ORA numerics (shared by the worker and tests)
js/worker.js               Web Worker: matching + hypergeometric + correction
js/app.js                  UI controller: state, table, charts, exports, permalink
images/Preview.png         favicon / og:image
data/                      committed gene-set JSON + manifest (built artifacts)
scripts/build_genesets.py  the build pipeline
tests/                     stats, data, and propagation tests
```

Data format: per species, `symbols.json` holds the unique symbol table (index =
gene id) plus `codingN` and an alias map; each collection file lists terms with
`genes` as integer indices into `symbols.json`. `manifest.json` lists the
collections (GO collections carry their `iea` variant as a sub-entry), the source
versions, and a build version token used for cache-busting.

## Deployment (GitHub Pages)

Served from the repository root of `main`: Settings > Pages > Build and
deployment > Source "Deploy from a branch", Branch `main`, folder `/ (root)`.
Asset URLs carry a `?v=<token>` from the manifest; after changing front-end
files, re-run the build (`--cache-raw --go --with-iea`) to rotate that token so
returning visitors load fresh assets.
